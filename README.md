# Wildpath · 越野路线规划器

Three.js 场景里对合成越野地形做采样、求解与行进闭环。规划不是从预设路线里挑一条，
而是每次根据当前装备、起终点与**装备耐久状态**重新搜索。

## 运行

```bash
npm install
npm start           # http://localhost:5173
npm test            # Node 端代价、搜索与耐久核验，23 + 18 项
npm run test:worker # 不依赖浏览器的 worker 消息/缓存/反例驱动检查
```

## 两套求解器，同一块地形

泥路前半段每米代价低，却快速磨损装备；后段碎石坡（gravel/costly）有耐久门限，
磨穿的装备无法通过，且剩余耐久越低、疲劳加价越高。两种实现都在
`src/durability.js` / `src/minimap.js`：

- **状态精确搜索（`solveDurability` / `solveGraph`）**：搜索状态是 `(节点, 剩余耐久 d)`。
  每个节点保留一条 Pareto 标签前沿——只有被“代价更低且耐久更高”的标签支配时才淘汰。
  便宜但磨装备的泥路标签因此不会被短视地删掉。
- **分层预估再局部精算（`solveHierarchical` / `solveGraphHierarchical`）**：第一层是
  完全不看耐久的基础代价 A*，得到粗路线；第二层只在粗路线的**拓扑走廊**（BFS 膨胀若干层）
  内做 `(节点, d)` 精算。粗层看不到碎石门限，可能承诺一条装备走不完的走廊；走廊失败时
  逐层加宽，最后回退到全图精确搜索。`trace` 记录每一层的展开数与成败。

### 缓存只在何种装备状态下有效

worker（`src/worker-durability.js`）缓存键由
`装备 :: 起点 :: 终点 :: 全部补给点有序坐标 :: 出发耐久 :: 求解器` 组成。
一个缓存条目**只在该装备状态（含补给位置与出发耐久）下有效**：拖动补给、更换装备或
改变出发耐久都会改变键，旧条目永不复用。界面直接展示当前键与命中/未命中。

## 补给点与实走记录

左侧补给箱可拖到地形任意可通行格（HTML5 拖放，落点射线检测并吸附到 2 m 格点），
松开即重新求解；补给半径内的节点把耐久恢复到满值。选择“按精确/分层路线走”后角色沿
被计价的折线实走，结束后记录：实际耗时、到达装备耐久、搜索扩展状态数、峰值标签数与
补给使用次数。

## 可枚举小地图、参照解与回退判据

`src/minimap.js` 在显式加权图上构造两张小到可穷举的地图，
`enumerateSimplePaths` 列出全部可行简单路径作为参照最优：

- **MUD_GATE**：便宜泥路与草地绕行二选一，泥路把耐久磨到碎石门限以下。粗层 A* 选泥路，
  其走廊精算不可达；记录在 `HIERARCHICAL_FAILURE_FIXTURE` 的输入触发
  `shouldFallback` 回退判据，回退后的全图精确解与穷举参照解一致。这是“分层法选错的
  输入”的可运行留档。
- **DIAMOND**：两条分支以**相同到达代价、不同剩余耐久**抵达汇合点 J（如代价 2.4 / 耐久 16
  对代价 3.0 / 耐久 97），其后接一段只有耐久足够才能越过的碎石路。

## 单标签淘汰反例（调试器）

调试器面板（worker 的 `minimap-debug` 消息）展示：在 DIAMOND 汇合点 J，若每个节点只留
一个标签（先到者占位），便宜的泥标签 `(g=2.4, d=16)` 会让更耐久的草标签 `(g=3, d=97)`
被提前淘汰；当碎石门限高于 16 时，单标签搜索判定不可达，而保留完整 Pareto 前沿的精确
搜索可达。`debugEvents` 逐点记录被丢弃的标签与保留标签，界面据此说明为何中间节点的
提前淘汰会破坏最终最优性。

## 核心设计（无耐久层）

**两层采样。** 地表真值是一张 0.2 m 细格（`src/terrain.js` 的 `surfaceClassAt`
与 `heightAt`）。搜索节点是 2 m 格点，但一条边的代价不由两端颜色决定，而是用
supercover 遍历把这条边穿过的每个细格按实际穿越长度累加（`traverseCells`）。

- 只有角点相触的格子以长度 0 参与遍历，因此斜穿不可通行格角点会被判为阻断，
  而不是“擦边通过”。
- 坡度用同一条边的行进方向、对同一个连续高度场做中心差分；对角边与正交边走
  同一段代码，√2 长度与坡度一致计费。
- 节点格点相对细格偏移半个格子，避免 2.0 m 恰好落在 0.2 m 格线上导致的
  轴向边归属抖动。

**不可通行 ≠ 高代价。** `impassable` 让边无效；`costly`（可行走碎石场与窄碎石缝）
代价有限但很高。两者在图里是不同状态，不会合并。

**启发式。** `h = minBase × 直线距离`。基础代价处处 ≥ minBase 且坡度系数 ≥ 1，
因此 h 可采纳且一致；不做权重膨胀。界面与测试都跑一遍 `h=0` 的 Dijkstra 对照。

**装备。** 三种装备有各自的草地/碎石/泥地/高代价单价、上下坡系数与坡度上限。
路线差异是搜索出来的结果：冰爪能翻西侧短陡脊（实测坡度越过靴子上限），
靴子被迫走东侧长缓鞍部，全地形车沿碎石带绕行。

## 界面

- 左侧可切换装备；切换即重新求解，路线随之改变。
- “耐久度求解”切换精确搜索 / 分层预估 / 两者对比，并显示展开状态数、峰值标签、回退。
- 补给箱拖放、实走记录、缓存键说明与小地图反例调试器都在左侧面板。
- “重新设置起终点”可武装拾取模式，点击地形放置起点或终点，吸附到 2 m 格点后重新求解。
- 无耐久 A* 面板保留作粗层对照，展示总代价、长度、上下坡附加、最高坡度与地表米数构成。

## 校验

- `tests/run-tests.mjs`（23 项）：细带积分、不可通行与高代价区分、斜穿角落阻断、
  对角长度/坡度、三种装备下 A* 与 Dijkstra 相等、启发式一致性、0.05 m 重积分等。
- `tests/durability-tests.mjs`（18 项）：小地图穷举参照解、精确搜索匹配穷举、
  分层走廊失败与回退、单标签淘汰反例、真实地形上的门限/疲劳/补给机制。
- `scripts/worker-driver.mjs`：在 Node 里模拟 worker，验证缓存键随装备状态变化、
  无补给不可达、调试反例载荷。
- 浏览器端到端脚本在 `scripts/smoke-durability.mjs`（需本机可用的 Chromium）。
